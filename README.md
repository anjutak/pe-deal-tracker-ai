# PE Deal Tracker
## AI-Powered Investment Deal Intelligence System

> A RAG-based prototype that enables private equity analysts to query historical deal knowledge using natural language — built with Claude API and vector database architecture.

**Course:** IMT 589C — Implementing & Managing AI Systems | University of Washington MSIM  
**Team:** Anjuta Khongbantabam & Xinxin Tai  
**Focus Areas:** RAG Architecture · Claude API Integration · GenAI Evaluation · AI Risk Assessment

## Problem Statement

Private equity firms sit on years of valuable deal data — but that institutional knowledge is effectively locked away. Three critical pain points drove this project:

| Problem | Impact |
|---|---|
| **Information fragmentation** | Deal data scattered across Excel, email, and shared drives — no unified query layer |
| **Knowledge loss** | When team members leave, their decision rationale and deal insights leave with them |
| **Inefficient research** | Analysts spend hours manually searching for comparable deals, slowing due diligence |

**Core insight:** This is not a data problem — it's an *access and retrieval* problem. The right architecture can surface institutional knowledge on demand.

---

## Solution Architecture

The PE Deal Tracker is a **Retrieval-Augmented Generation (RAG)** system that allows analysts to ask questions in plain English and receive answers grounded in the firm's actual historical deal data.

```
User Query (Natural Language)
        ↓
  Vector Embedding
        ↓
Semantic Search → Vector Database (historical deals)
        ↓
  Retrieved Context
        ↓
  Claude API (LLM)
        ↓
  Grounded Answer
```

### Why RAG?
RAG was chosen over fine-tuning because:
- Deal data changes frequently — RAG allows real-time updates without retraining
- Answers are grounded in actual documents, reducing hallucination risk
- Citations can (in future versions) point directly to source deals

## AI Evaluation & Risk Assessment

A key contribution of this project was applying a **systematic QA lens** to the GenAI prototype — treating the AI system as a product that needs testing, not just building.

### Risks Identified
| Risk | Mitigation Strategy |
|---|---|
| **Data privacy compliance** | Anonymization pipeline; no PII in vector DB |
| **AI accuracy / hallucination** | Citation tracking; human-in-the-loop validation |
| **User adoption** | UX research; analyst onboarding strategy |
| **Data quality** | Input validation; governance framework for deal data |

### Evaluation Criteria Used
- **Factual grounding** — do answers trace back to real deal records?
- **Response relevance** — does the LLM answer the actual question asked?
- **Failure mode documentation** — what types of queries break the system?
- **Scope boundary testing** — how does the system behave on out-of-domain queries?

## Automated QA Suite

The [`qa-suite/`](qa-suite/) folder contains an automated evaluation suite for a Langflow version of the tracker: a 27-case golden dataset, keyword checks, a **Claude LLM-as-judge** that scores correctness, grounding, and scope, repeat-run flakiness measurement, and judge validation against hand labels.

**Highlights:** 6 defects found (2 prompt bugs fixed and confirmed with a regression run); the LLM judge found twice as many bugs as keyword checks; one question passed 100% of keyword checks while its supporting numbers were wrong in every run. See [qa-suite/README.md](qa-suite/README.md) for full results.
